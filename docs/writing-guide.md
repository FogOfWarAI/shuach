# 怎样写 GameMatch 文档

先确定读者手里有什么、想得到什么。假设读者已经选好两队英雄，想算左队胜率。这时先交代去哪里找训练好的模型，再给一组能传给预测器的 ID，最后解释返回数组里的那一个数。

## 一条 API 说明应回答什么

| 读者的问题 | 以 `HeroPredictor.predict` 为例 |
| --- | --- |
| 我先要准备什么？ | 一次完成的英雄阵容训练。用训练产生的 seed/model 目录创建预测器，保留上一级目录中的词表。 |
| 我传入的东西代表什么？ | 原始英雄 ID，整数数组形状为 `[N, 2, 5]`。三个维度依次是对局、左右两队、每队五名英雄。给一局也要保留最外层。 |
| 我会拿到什么？ | 长度为 `N` 的概率数组。`p[i]` 对应第 `i` 局左队获胜的概率，可以直接解释。 |
| 最容易出错的是哪一步？ | 预测器读取原始 ID 并应用训练词表。直接调用底层网络时，却要传已经编码的索引，并将返回的 logit 转为概率。 |
| 我怎么知道例子跑对了？ | 用断言检查输出形状和概率范围。涉及训练时说明数据、种子和目录，给出独立可运行的前置命令。[完整范例](model-additions.md) |

## 给示例选一个能看懂的结果

分队示例里，四个玩家的评分是 8、7、3、2。把目标写成「最小化两队总评分之差」，读者就能用 8＋2＝7＋3 核对 `cost == 0`。如果换成预测胜率，要明确目标是距 0.5 的距离。两种例子里的 `cost` 单位不同。

用真实数据时，先写预测发生的时点。例如，评级器只有在前一局结果已可见时才能更新玩家状态。说明每一列的顺序，尤其是三分类的「负、平、胜」和五分类的「击杀数 0 到 4」。复用论文方法时链接原论文或作者实现，写出本库改动的输入、训练和评价方式。

## 提交前如何检查

从读者所在的目录重跑命令。确认示例的导入路径、关键词参数、返回值和异常与当前版本相符。无数据的入门示例可以直接加入文档测试；需要已有检查点的示例先运行所列训练命令。

```bash
python -m unittest discover -s tests -p 'test_documented_examples.py'
```

新增公共接口时同步更新对应的 Python docstring 和 [API 导航](api.md)。新增模型时同步写明模型 ID、输入类别、依赖、输出和来源。数据准备、指标定义和高级训练参数可放在 [研究接口](research-api.md)，让入门页保留完成第一项任务所需的信息。
